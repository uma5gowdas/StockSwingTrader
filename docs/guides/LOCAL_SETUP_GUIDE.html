Step 0. What this is (read first)

StockSwingTrader is a set of Bash, Python and Node tools for swing-trading analysis: technical indicators, a confluence score, an XGBoost direction predictor, regime detection, a Kalman filter, a backtester and a React dashboard. This guide takes you from the private GitHub repo to a working local install.

Disclaimer. Not financial advice. Use paper trading only. The XGBoost model is trained on synthetic data (every prediction says "model_training_data": "synthetic"), so its output is not evidence of anything about real markets.

How this guide was verified. The repo was cloned fresh into /tmp/sst-fresh and every step was run there. The guide uses ~/Projects/StockSwingTrader as the folder; the commands are the same. Steps that could not be run on the test Mac (Homebrew installs, gh/SSH login, the Python 3.11 path, pressing Ctrl+C) are tagged not run. Commands that ran and worked are tagged verified. Known failures are tagged known issue, each with a workaround that does work.

The value demo (and empty values or YOUR_...) means "not configured": sentiment is then skipped and gets no weight. Market prices come from Yahoo Finance via yfinance and need no key.

Changing a key

  1. Edit config.sh (open -e config.sh or any editor). Use a plain assignment, for example export API_KEY_FINNHUB="new_key". Do not use the ${VAR:-...} form: the template is loaded first and has already set API_KEY_FINNHUB/API_KEY_NEWSAPI to demo, so a :- default never applies.
  2. Run the check above again, then ./StockSwingTrader_Agent.sh --check-account for Alpaca keys.
  3. Commit it to the private repo: git add config.sh && git commit -m "chore: rotate keys". git status shows config.sh as modified after every edit; that is expected now.

If a key was ever shared outside the private repo (chat, email, screenshot, a public fork), regenerate it: Alpaca dashboard → Paper account → API Keys → Regenerate; finnhub.io dashboard; newsapi.org account. Then update config.sh as above.

Never put live keys or a live URL in config.sh. It is tracked in git. The agent refuses broker commands on a LIVE endpoint while the active config file is tracked (LIVE endpoint refused: config.sh is tracked in git ...). Live keys belong in an untracked config.live.sh (gitignored), selected per command with SST_CONFIG_FILE and confirmed with --live:

SST_CONFIG_FILE="$PWD/config.live.sh" ./StockSwingTrader_Agent.sh --buy AAPL 1 --live   # then type: AAPL 1

not run against a live account (tested only against a local stand-in on 127.0.0.1). This guide is for paper trading.

v2 scoring (default) and --legacy-score

The CLI scores every symbol with the v2 confluence score: 15% ML prediction + 35% regime-weighted mean-reversion/trend-following + 30% technical (RSI, MACD, Bollinger) + 20% volume/trend (a real OBV trend score blended with the Kalman trend). All inputs come from the 60 daily bars already fetched. When news sentiment is available it gets 10% (V2_SENTIMENT_WEIGHT) and the other weights shrink to make room; without it, sentiment has 0 weight. --legacy-score (or SCORING_MODE=legacy) uses the old formula: 80% average of six indicators + 20% sentiment.

SST_OFFLINE=1 ./StockSwingTrader_Agent.sh --symbols AAPL --output-dir /tmp/sst-reports
./StockSwingTrader_Agent.sh --symbols AAPL --legacy-score
SCORE BREAKDOWN (v2: 15% ML + 35% regime-weighted MR/TF + 30% technical + 20% OBV/Kalman volume-trend; sentiment 0.10 when available)
AAPL  score 48 HOLD | ML 82 up (15%) | Regime 28 trending_bear (35%) | Technical 48 (30%) | Volume/Trend 57 (20%) | Sentiment n/a (0%) | OBV 65 | data synthetic

What happens on --buy / --sell

  1. Before contacting the broker: symbol and quantity, --limit-price, kill switch, live guard, MAX_ORDER_QTY.
  2. Alpaca: market hours, reconciliation, daily loss halt.
  3. Positions and caps (no short selling), duplicate guard, price, limit price, daily notional, bracket levels, PDT warning.
  4. Confirmation: type yes (paper / local stub) or, on a LIVE endpoint, the symbol and quantity (e.g. AAPL 2).
  5. The order is written to the order ledger (.state/orders.jsonl), sent with a client order id (sst-...), and an alert is written to logs/alerts.log.

The first failed check stops the order with a message and exit code 1; nothing is sent.

Reconciliation

The agent keeps a baseline of your positions (.state/positions_baseline.json) and a ledger of its own orders. Before an order it checks that the broker's positions equal the baseline plus the agent's filled orders, and that there are no unknown open orders. Trades you make elsewhere (Alpaca website, app) show up as a mismatch and block orders until you review them with --reconcile and adopt them with --reconcile-accept (or use --allow-mismatch for one order).

Market hours and PDT

Outside market hours (Alpaca clock) or on a holiday (Alpaca calendar) orders are refused (Order blocked: the market is closed ...), unless OUTSIDE_HOURS_POLICY=queue. If the clock cannot be read the order is refused. Below $25,000 equity the agent prints a PDT WARNING when an order could create a same-day round trip (a sell of a symbol bought today, or any bracket buy); it does not block.

Alerts

Order placed / filled / rejected, cap hits, duplicates, halts, resume, reconciliation mismatches, outside-hours refusals and PDT warnings are written to logs/alerts.log. Slack and email are off by default; set ALERTS_SLACK_ENABLED=true and the webhook URL (or the email variables) to turn them on. Keep the webhook URL out of tracked files if the repo is ever shared. Channel failures never stop the agent.
