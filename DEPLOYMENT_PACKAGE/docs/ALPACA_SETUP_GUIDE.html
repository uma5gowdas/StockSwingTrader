Getting Started with Alpaca

What is Alpaca?

Alpaca is a modern broker that provides commission-free stock trading, real-time market data, and a powerful API for algorithmic trading. Whether you're a beginner or an experienced trader, Alpaca offers the tools you need.

Key Features

  • Commission-Free Trading: Trade without paying commissions on stocks and ETFs
  • Paper Trading Account: Practice with virtual money before trading with real funds
  • Real-Time Market Data: Access live stock quotes and market information
  • Powerful API: Build algorithmic trading strategies programmatically
  • Multiple Data Feeds: Choose between SIP (detailed) or market data feeds
  • 24/5 Trading: Trade during regular market hours
💡 Pro Tip: Alpaca provides both live trading and paper trading. We recommend starting with a paper trading account to test your strategies risk-free.

Account Types

Live Trading Real money, actual stock transactions Deploying tested strategies

Security Best Practices

⚠️ Critical: Your API keys are as valuable as your trading account. Treat them with the same care as you would a password. If they're compromised, someone could trade with your money.

Never Commit API Keys to Git

Why? If your API keys are committed to a public repository, anyone can access them and potentially trade with your account.

// ❌ NEVER DO THIS
const API_KEY = "PK_LIVE_1234567890abcdef";
const SECRET_KEY = "abcdef1234567890ABCDEF";

module.exports = { API_KEY, SECRET_KEY };

Even in private repositories, hardcoding credentials is a security risk.

Use Environment Variables

Store your API keys as environment variables. These are kept separate from your code and never committed to version control.

# Set environment variables (in bash)
export ALPACA_API_KEY="your_api_key_here"
export ALPACA_SECRET_KEY="your_secret_key_here"

# Access in your code
const apiKey = process.env.ALPACA_API_KEY;
const secretKey = process.env.ALPACA_SECRET_KEY;

Use Config Files Outside Git

If using a configuration file approach, store credentials in a file that's excluded from git.

# Add to your .gitignore
config/api_keys.sh
config/credentials.json
.env
.env.local
.env.*.local

Then create a template file that developers can copy and fill with their own credentials:

# config/api_keys.sh.example
export ALPACA_API_KEY="YOUR_API_KEY_HERE"
export ALPACA_SECRET_KEY="YOUR_SECRET_KEY_HERE"
export ALPACA_ENV="paper"  # or "live" for production

Other Security Best Practices

  • Rotate Keys Periodically: Generate new API keys every 3-6 months and deactivate old ones
  • Use Different Keys for Different Environments: One key for paper trading, another for live trading
  • Limit Key Permissions: If Alpaca offers permission scoping, restrict keys to only necessary actions
  • Monitor API Usage: Regularly check your Alpaca dashboard for unusual API activity
  • Enable Account Alerts: Set up notifications for large trades or account changes
  • Use HTTPS: Always communicate with Alpaca over HTTPS (never HTTP)
  • Secure Your Dev Machine: Keep your development environment updated with security patches

If Your Keys Are Compromised

🚨 Immediate Action Required:
  1. Log into your Alpaca account immediately
  2. Go to Settings > API Keys
  3. Delete or deactivate the compromised key
  4. Generate a new API key pair
  5. Update your configuration with the new keys
  6. Monitor your account for any unauthorized activity

Configuration Setup

Overview

Once you have your API keys, you need to configure your environment to use them. There are several ways to do this, depending on your preference and use case.

Option 1: Environment Variables (Recommended)

This is the simplest and most secure approach for local development.

On macOS/Linux:

# Open or create ~/.bashrc or ~/.zshrc
nano ~/.zshrc

# Add these lines at the end
export ALPACA_API_KEY="your_api_key_here"
export ALPACA_SECRET_KEY="your_secret_key_here"
export ALPACA_BASE_URL="https://paper-api.alpaca.markets"

# Save and exit (Ctrl+X, then Y, then Enter)

# Reload the shell configuration
source ~/.zshrc

On Windows (PowerShell):

# Open PowerShell as Administrator
# Set environment variables
[System.Environment]::SetEnvironmentVariable("ALPACA_API_KEY","your_api_key_here","User")
[System.Environment]::SetEnvironmentVariable("ALPACA_SECRET_KEY","your_secret_key_here","User")
[System.Environment]::SetEnvironmentVariable("ALPACA_BASE_URL","https://paper-api.alpaca.markets","User")

# Restart PowerShell to apply changes

Verify the Configuration:

# macOS/Linux
echo $ALPACA_API_KEY

# Windows PowerShell
$env:ALPACA_API_KEY

Option 2: Configuration File

Create a shell script or config file to load your credentials. This is useful if you manage multiple API keys or environments.

#!/bin/bash
# config/api_keys.sh
# Configuration file for Alpaca API keys
# ⚠️ IMPORTANT: Add this file to .gitignore

# Your Alpaca API Key
export ALPACA_API_KEY="your_api_key_here"

# Your Alpaca Secret Key
export ALPACA_SECRET_KEY="your_secret_key_here"

# Environment: "paper" for paper trading, "live" for real trading
export ALPACA_ENV="paper"

# Base URL (automatically set based on ALPACA_ENV)
if [ "$ALPACA_ENV" = "paper" ]; then
    export ALPACA_BASE_URL="https://paper-api.alpaca.markets"
else
    export ALPACA_BASE_URL="https://api.alpaca.markets"
fi

# Data API URL
export ALPACA_DATA_URL="https://data.alpaca.markets"

# Optional: API timeout in seconds
export ALPACA_TIMEOUT="30"

echo "✓ Alpaca API configuration loaded"

How to Use This File:

# Source the configuration in your script
source config/api_keys.sh

# Now you can use the environment variables
echo $ALPACA_API_KEY
echo $ALPACA_BASE_URL

Add to .gitignore:

echo "config/api_keys.sh" >> .gitignore

Option 3: .env File (for Node.js/Python)

If you're using Node.js with the dotenv package or Python with python-dotenv, you can use a .env file.

# .env (DO NOT COMMIT TO GIT)
ALPACA_API_KEY=your_api_key_here
ALPACA_SECRET_KEY=your_secret_key_here
ALPACA_ENV=paper
ALPACA_BASE_URL=https://paper-api.alpaca.markets

Testing Your Credentials

Why Test?

Before integrating Alpaca into your trading application, it's important to verify that your API credentials are valid and that you can successfully connect to the Alpaca API.

Test 1: Using curl (Command Line)

The simplest way to test your credentials is using curl to make a direct API request.

curl -H "APCA-API-KEY-ID: $ALPACA_API_KEY" \
  -H "APCA-API-SECRET-KEY: $ALPACA_SECRET_KEY" \
  https://paper-api.alpaca.markets/v2/account

Common Error Responses

401 Unauthorized

Cause: Invalid API key or secret key

Solution:

  • Verify the keys match exactly (copy/paste from Alpaca dashboard)
  • Check for extra spaces at the beginning or end of keys
  • Regenerate the API key if you suspect it's corrupted
403 Forbidden

Cause: API key doesn't have required permissions

Solution:

  • Verify the key was created in your Alpaca account
  • Check if your account is in good standing
  • Try regenerating the API key
Connection Timeout

Cause: Network issue or Alpaca server unreachable

Solution:

  • Check your internet connection
  • Verify Alpaca API status at status.alpaca.markets
  • Check if your network blocks outbound connections to Alpaca
  • Try from a different network
rate_limit_exceeded

Cause: You've exceeded Alpaca's API rate limits

Solution:

  • Alpaca has rate limits: 200 requests per minute for paper trading
  • Wait a minute before retrying
  • Implement rate limiting in your application

Test 2: Using Python

#!/usr/bin/env python3
import os
import json
import requests

# Load environment variables
api_key = os.getenv('ALPACA_API_KEY')
secret_key = os.getenv('ALPACA_SECRET_KEY')
base_url = os.getenv('ALPACA_BASE_URL', 'https://paper-api.alpaca.markets')

# Verify variables are set
if not api_key or not secret_key:
    print("❌ Error: ALPACA_API_KEY or ALPACA_SECRET_KEY not set")
    exit(1)

# Make the API request
headers = {
    'APCA-API-KEY-ID': api_key,
    'APCA-API-SECRET-KEY': secret_key,
}

try:
    response = requests.get(f'{base_url}/v2/account', headers=headers, timeout=10)
    
    if response.status_code == 200:
        print("✅ Connection successful!")
        account = response.json()
        print(f"\nAccount Information:")
        print(f"  Status: {account['status']}")
        print(f"  Buying Power: ${account['buying_power']}")
        print(f"  Cash: ${account['cash']}")
        print(f"  Portfolio Value: ${account['portfolio_value']}")
    else:
        print(f"❌ Error: {response.status_code}")
        print(f"  {response.text}")
except Exception as e:
    print(f"❌ Connection failed: {e}")

Test 3: Using Node.js

// test_alpaca.js
const https = require('https');

const apiKey = process.env.ALPACA_API_KEY;
const secretKey = process.env.ALPACA_SECRET_KEY;
const baseUrl = process.env.ALPACA_BASE_URL || 'https://paper-api.alpaca.markets';

if (!apiKey || !secretKey) {
    console.error('❌ Error: ALPACA_API_KEY or ALPACA_SECRET_KEY not set');
    process.exit(1);
}

const options = {
    hostname: baseUrl.replace('https://', ''),
    path: '/v2/account',
    method: 'GET',
    headers: {
        'APCA-API-KEY-ID': apiKey,
        'APCA-API-SECRET-KEY': secretKey,
    },
};

const req = https.request(options, (res) => {
    let data = '';
    
    res.on('data', (chunk) => {
        data += chunk;
    });
    
    res.on('end', () => {
        if (res.statusCode === 200) {
            console.log('✅ Connection successful!');
            const account = JSON.parse(data);
            console.log('\nAccount Information:');
            console.log(`  Status: ${account.status}`);
            console.log(`  Buying Power: $${account.buying_power}`);
            console.log(`  Cash: $${account.cash}`);
            console.log(`  Portfolio Value: $${account.portfolio_value}`);
        } else {
            console.error(`❌ Error: ${res.statusCode}`);
            console.error(`  ${data}`);
        }
    });
});

req.on('error', (e) => {
    console.error(`❌ Connection failed: ${e.message}`);
});

req.end();

How to Use:

node test_alpaca.js

Understanding Open Positions

Open positions show stocks you currently hold. Each position displays:

  • Symbol: Stock ticker (e.g., AAPL, GOOGL)
  • Quantity: Number of shares owned
  • Entry Price: Average price you paid per share
  • Current Price: Latest market price
  • P&L: Profit/Loss in dollars and percentage
💡 Example: If you bought 10 AAPL at $180 (total $1,800) and it's now at $185, your P&L is +$50 (+2.78%).

Paper Trading vs Live Trading

Aspect Paper Trading Live Trading
Money Virtual - $100,000 free Real money you deposit
Risk No financial risk Real financial risk
Execution Instant fills (simulated) Real market execution
Data Same as live Real market data
Best For Testing strategies, learning Real trading
⚠️ Recommendation: Always thoroughly test your trading strategy in paper trading mode before deploying to live trading.

Paper Trading Safety Notes

  • Paper trading resets daily - your positions don't carry over
  • Fills are simulated and may not match real execution
  • Market impact (your large orders affecting prices) is not simulated
  • Commissions and fees are not deducted
  • Use it to verify logic, not to predict live performance

Troubleshooting Guide

Error: 401 Unauthorized

Error Message: 401 Unauthorized

What it means: Your API credentials are invalid or incorrect.

Common Causes:

  1. Typo in API key or secret key
  2. Extra spaces before or after the keys
  3. Using someone else's API key
  4. API key was deleted or revoked
  5. Environment variables not properly set

How to Fix:

  1. Log into Alpaca dashboard
  2. Go to Settings → API Keys
  3. Verify your API key is listed and active
  4. Copy the API key and Secret Key again (carefully)
  5. Update your environment variables or config file
  6. Test the connection again using curl

Last Resort - Generate New Keys:

  1. In Alpaca dashboard, click the trash icon to delete old key
  2. Click "Create Key" to generate a new one
  3. Copy both the API Key and Secret Key immediately
  4. Update your configuration with the new keys

Error: 403 Forbidden

Error Message: 403 Forbidden

What it means: Your API key doesn't have permission to perform this action.

Common Causes:

  1. Account is not fully verified
  2. Account is restricted due to pattern day trading rules
  3. Alpaca account is closed or suspended
  4. Insufficient funds for trading

How to Fix:

  1. Log into your Alpaca account
  2. Check account status in Dashboard
  3. Complete any pending verifications or requirements
  4. If paper trading, ensure it's enabled
  5. For live trading, verify sufficient funds are deposited
  6. Contact Alpaca support if account is suspended

Error: Connection Timeout

Error Message: Connection timed out or Network unreachable

What it means: Cannot reach Alpaca's servers.

Common Causes:

  1. No internet connection
  2. Network blocks outbound HTTPS connections
  3. Alpaca servers are down or slow
  4. Wrong base URL configured
  5. Firewall or proxy blocking the connection

How to Fix:

  1. Test basic internet: ping google.com
  2. Check Alpaca status: status.alpaca.markets
  3. Verify base URL is correct: 
    echo $ALPACA_BASE_URL
  4. Try with a different network (e.g., mobile hotspot)
  5. Check if your network blocks HTTPS traffic
  6. Try increasing the timeout: 
    curl --max-time 30 https://paper-api.alpaca.markets/v2/account

Error: Rate Limit Exceeded

Error Message: rate_limit_exceeded or 429 Too Many Requests

What it means: You've made too many API calls in a short time.

Alpaca Rate Limits:

Account Type Rate Limit
Paper Trading 200 requests/minute
Live Trading 200 requests/minute

How to Fix:

  1. Stop making API calls and wait 1 minute
  2. Implement request batching in your code
  3. Add delays between requests: 
    import time
time.sleep(0.5)  # Wait 500ms between requests
  4. Cache responses instead of making repeated calls
  5. Use WebSocket for real-time data instead of polling

Error: Invalid Base URL

Error Message: invalid_url or connection refused

What it means: The API endpoint URL is incorrect.

Correct URLs:

Purpose Correct URL
Paper Trading API https://paper-api.alpaca.markets
Live Trading API https://api.alpaca.markets
Data API https://data.alpaca.markets

How to Fix:

  1. Verify your base URL is spelled correctly
  2. Make sure it includes https:// (never http://)
  3. Check environment variable: 
    echo $ALPACA_BASE_URL
  4. Update if needed: 
    export ALPACA_BASE_URL="https://paper-api.alpaca.markets"

Error: Environment Variables Not Set

Error Message: ALPACA_API_KEY not found or similar

What it means: Your environment variables are not accessible to the application.

How to Fix:

  1. Verify variables are set: 
    echo $ALPACA_API_KEY
echo $ALPACA_SECRET_KEY
  2. If empty, set them now: 
    export ALPACA_API_KEY="your_key_here"
export ALPACA_SECRET_KEY="your_secret_here"
  3. If you're using a config file: 
    source config/api_keys.sh
echo $ALPACA_API_KEY  # Should show your key
  4. If using .env file, verify it exists: 
    ls -la .env
  5. If running in a new terminal, add to .bashrc or .zshrc: 
    echo 'export ALPACA_API_KEY="your_key"' >> ~/.zshrc
echo 'export ALPACA_SECRET_KEY="your_secret"' >> ~/.zshrc
source ~/.zshrc

Error: Invalid JSON Response

Error Message: JSON decode error or Invalid JSON

What it means: The API response is not valid JSON (might be HTML error page).

How to Fix:

  1. Check the actual response: 
    curl -v https://paper-api.alpaca.markets/v2/account \
  -H "APCA-API-KEY-ID: $ALPACA_API_KEY" \
  -H "APCA-API-SECRET-KEY: $ALPACA_SECRET_KEY"
  2. Look for error messages in the response
  3. Verify the endpoint is correct
  4. Check API documentation for correct request format
